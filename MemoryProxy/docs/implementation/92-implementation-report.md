## 2. 思路：怎么实现的

### 2.1 三条设计原则（先立原则，再写代码）

1. **口径先行**：**先定义"什么算被引用"**，再写实现；判据的形态假设必须覆盖**实际**形态（不是"我以为的形态"）。
2. **判据取精确通道**：数值型基线/期望值**只从精确通道取**（精确分数 / 语言层真值 / `printf('%.17g')`），**不得取自显示层**（SQLite 默认显示、`toFixed`、`console.log` 默认精度）；对账用**数值比较**，字符串形态只作并列供人读。
3. **fail-closed 与"静默即缺陷"**：危险动作**默认禁写**（见红线二）；**任何"应当发生的写入"都必须能两侧对账** —— 不接受"没写但没痕迹"。

### 2.2 关键机制

| 机制 | 为什么这样设计 |
|---|---|
| **`decision_unit` 编码**（`anchor×16 + slot`） | 一个"决策锚"下可有多个事件位，**幂等键天然唯一**，且能与消息下标互相反查 |
| **影子指标 + 两档门槛** | 先把**测量**做出来（逐候选连续重合/跨度/归一化），**再谈裁决**；测量与裁决解耦，才能做标定 |
| **变更锚定独立于归档** | 归档只保"有可见文本"的行（纯 `tool_use` 的助手轮可见文本为空）⇒ **变更必须从消息面直接派生**，否则结构性丢失 |
| **回执信息架构**：摘要 → 三档 → 展开 → 为什么 | 老师/用户的第一屏是**"本次用了什么"**；细节按需展开；**缺值一律渲染"未知"，不臆造**（不用 0 或空串冒充） |
| **"为什么适用于当前任务"** 四档 | 只从**已有素材**派生（`verdict` / `citationMetrics` / `shortlist` 溢出面），**零新增拉取、零 LLM、不新造阈值**；素材缺失 ⇒ 如实"未知" |

### 2.3 判据与制度的配合（红线为什么是机械的）

- **红线一**（`confirmed` 只代表整段逐字级引用）：把文本重合**降格为筛选信号**，`confirmed` 稀少是**设计结果**；
- **红线二**（`asset_validated` 禁写）：事件白名单 **fail-closed**，`asset_used` / `asset_corrected` 之外的状态事件**写不进去** ⇒ 回执里**不会出现"已验证"**，只会显示"已采用／已校正／仅背景参考，效果待验证"。

## 3. 遇到的挑战（本报告的重点）

> 每一条都给出**怎么发现的 → 怎么处理 → 沉淀成什么规则**。这些都是真实的、被记录在案的弯路。

### 挑战 1｜"链路在跑" ≠ "端到端真的通"

- **现象**：归档/注入/单元三段在真库上**双侧非零**（`hook.done 16 / block_seen 5`），可**客户端一个字都拿不到** —— 上游配置还是**占位域名**，请求在 **FORWARD 阶段 502**。
- **处理**：把"打通端到端"的验收**必须落在末端产物**上（真实补全文本 + 客户端 200 + 上游模型名回显），并配**同族反控**（把上游换回占位域 ⇒ **必须 502**）。
- **规则**：**末端产物判据**（"链路每一段都会各自声称在跑"）。

### 挑战 2｜默认关闭的开关 + 部署配置代际（"代码在盘上 ≠ 在跑"）

- **现象**：两个真实会话（`hook.done` 32/48 次）的 `block_seen` **0 行**、无水位 —— 合计 **116 事件 ≈ 全库 29%** 的可见文本**从未进档**；而当天稍后的会话一切正常 ⇒ 成因是**进程/配置代际**（配置里三键缺省 `false`）。另一次：变更行代码已提交，但**运行中的进程早于该提交**。
- **处理**：① 做出**两侧对账入口**（把"静静漏掉"变成一条命令看得见，并**点名"有上游而下游为 0"的键**）；② 缺口**不回填**（留作物证），但要证明**缺口不再增长**；③ 时间性推断**不如一个行为证据**（用"新事件类型首次出现"证明新代码真的在跑）。
- **规则**：**静默不写必须两侧对账**；**部署配置 ↔ 开关清单必须逐条核对**。

### 挑战 3｜判据的"形态假设"没覆盖实际形态

- **现象 A**：我在冻结基线里把一个数值期望值写成了 **15 位有效数字的截断形态**（取自 SQLite 默认显示），parse 回来与存储真值差 **2.08e-17 ≈ 3 ulp** ⇒ 验收时出现"唯一未过格"。追到底是**期望值错了**，不是实现漂移。
- **现象 B**：随后又把主字段写成 `toFixed(16)` —— **实测它非单射**：会把**约 19 个相邻 double 压成同一个字符串**（`1 ulp = 6.94e-18` vs `1e-16` 分辨率，**粗 14.4 倍**）⇒ 用它当主字段，**±9 ulp 的漂移在主字段上字面同串**，等于**把漂移检测器的最后一位屏蔽掉**。
- **处理**：主字段改为**最短往返形态（17 字符，单射）**；并列保留人读形态；**不改判据、不用容差**。
- **规则**：**数值型期望值必须取自精确通道**；**冻结基线一旦更正，所有"与基线同形/同值"的引用必须同批检查**。

### 挑战 4｜口径与数据现实的冲突（不调阈值凑数）

- **现象**：真实数据上，**改写型反例的重合度最高 0.877，而正例最低只有 0.605** ⇒ 两者区间**重叠、当前口径下不可分**；现库真实会话中**最大连续重合仅 3 字符**（阈值需 24）。⇒ 正例长期为 **0**。
- **处理**：**不调门槛、不放宽口径**；把"0 候选"做成**可分**的报告（候选总数 + 逐行形状 + 全局分布 + 各轴 max）⇒ 明确"属**真没有候选**（取数口径正常）"；同时把"观测面缺口"（挑战 2）与"确实没有引用"**分开**。
- **规则**：**不得调阈值掩盖数据不足**；落空报告必须**能自证口径正常**。

### 挑战 5｜账要能对上（停在该停的地方）

- **现象**：设计目标是"资产→决策→变更/结果"的**可核关联**，实测**锚定面 34/35 ≈ 97%**，但**变更类 0 条可判定**（档② 无 `assistant` 行 ⇒ 拿不到工具名）。
- **处理**：**不为凑数放宽门槛**，当场停在"量化 + 诚实登记"，并把前置登记进下一张单；后续正是据此做成了 `agent.tool.change`（并证明**从消息面派生**才是不丢数据的做法）。
- **规则**：**单内预设终点**（允许停在"量化 + 登记"）；**写库的单要用"逐表增量 = 已知量且可解释"当门**（不是"指纹不变"）。

### 挑战 6｜端到端落地时的"隐性前提"

- **现象（四个，全在真跑时撞上）**：
 1. **Model gate**：价目表已配置时，客户端 `model` 必须匹配某条 `modelName`，否则 **400 `model_not_found`**（⇒"只填上游 URL"根本跑不通）；
 2. **两把钥匙**：上游 key（服务端）与客户端 `user_key`（内核签发）**不是一回事**，混用 ⇒ **401**；
 3. **身份头缺失 ⇒ 200 但零观测**：只带 `Authorization` 的请求能拿到真实补全，但**注入/归档/归因整段不跑**（session init 未成立）；
 4. **接口文档示例 ≠ 本栈实况**：文档给的端口/会话头名与本栈不一致（示例端口无人监听；某两级的会话头**本栈代码里不存在**）。
- **处理**：逐条核回代码与真库，把"能开但空"的结构性成因写进部署与验收单。
- **规则**：**接口文档的接入示例必须逐字核回本栈（地址/版本/字段语义/头链四处）**。

### 挑战 7｜统计与自检自身的坑（"验证据的工具"也会骗人）

- **现象（四种，一天内全中）**：
 1. 循环里用了 `for f in $MULTILINE`，而 **`zsh` 不对未加引号的参数做字段分割** ⇒ 整个多行被当成**一个**文件名 ⇒ 45 个文件被误报成"缺失 1"；
 2. 把**被 `cut` 截断过的输出**当成全集 ⇒ 集合基数数错；
 3. 比哈希时路径写错，两边都取到**空串的 sha256（`e3b0c442…`）**，却显示"相同" ⇒ **假阳性**；
 4. 统计"仓库被引用的单号"时**把索引文件自身算了进去** ⇒ **自指污染**（含自身 58 / 排除自身 37）。
- **处理**：逐条重做并**把采集命令原样写进文档**（带 `--exclude`、带 `wc -l`、先在样本上验证循环逐项跑了）。
- **规则**：**统计四戒**（循环先验证／计数先 `wc -l`／空哈希当异常／采集集合不得含被验收对象自身）。

### 挑战 8｜"不声明"必须是机械的，而不是靠自觉

- **现象**：题目要求"只有任务结果或独立验证器能证明正向作用时，才可以声明资产产生了效果"。
- **处理**：把这句话做成**代码级约束**（白名单 fail-closed 禁写 `asset_validated`），宁可在界面上长期显示"待验证"，也不允许在无验证器时写下"已验证"；并把"谁能签这个字"作为**显式裁定**留痕（不靠倒计时逼出来）。
- **规则**：**红线要用机制保证，不用自觉保证**。

## 6. 我们如实呈现的限制（不藏）

| 限制 | 原因 |
|---|---|
| "已验证"档长期为空 | **红线二**：没有独立验证器就禁写（有意设计） |
| 正例长期稀少 | **红线一**：`confirmed` 要求整段逐字；现库最大连续重合 3 字符（阈值 24）⇒ **数据不足**如实上报 |
| 两个历史会话 ≈29% 可见文本未进档 | 已定位为**部署配置代际**，**不回填**（留作物证）；入口可点名，**缺口不再增长** |
| 回执"使用位置 / 对应代码改动"依赖本次真实会话 | 锚定链已通；未跑会话时如实显示空态文案（不用近似数据填） |
| 效果类结论 | **一律标注"待任务五评测"** —— 本线不越界声明效果（反事实比较不在范围内） |
